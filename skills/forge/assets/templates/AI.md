## Purpose

Project-local FORGE execution config and non-negotiable constraints.

## Constraints

- Execute one bounded task at a time.
- Use Conventional Commits for governed task commits.
- Do not include AI attribution, agent branding, or "generated by" lines in commits.
- In solo mode, complete one task, update the configured task source, commit, then stop unless the user explicitly allows continuing.
- `task_source: local` uses `TASKS.index.yaml` plus `docs/forge/tasks/`, or legacy `TASKS.yaml`.
- `task_source: github` or `gitlab` uses issue assignment, labels, comments, and PR/MR links as the ledger.
- `task_source: external` uses only the configured MCP, CLI, or human-provided tracker reference.
- `solo_branch_flow: task-branches` means do not work on or merge to `release_branch` without explicit human instruction.
- In team mode, claim before implementation, honor `file_scope`, reconcile before state transitions, and use PR/MR review.
- If `application_docs: true`, update triggered human-facing docs in the same task.
- Stop on ambiguity, missing prerequisites, branch conflicts, architecture conflict, unresolved security concerns, or failed checks without accepted exception.

## Context Discipline

Use minimum necessary project context.

Default read order:

1. This file.
2. `docs/forge/CONTEXT.md` if present.
3. Compact task index or configured tracker.
4. One selected task.
5. Task-relevant source files only.

Do not automatically read all tasks, memory, architecture docs, team docs, setup docs, prior decisions, or security checklists.

Escalate context only when the selected task requires it, and prefer the smallest relevant file or section.
